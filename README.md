# 圣遗物词条概率分布

> 原神五星圣遗物副词条的概率计算器。给定部位、主词条与计分词条权重，算出胚子练满 +20 后的得分分布，以及掉落瞬间的胚子质量。

## 使用

仓库根的 `index.html` 是**自包含单文件**：JS 与 CSS 已内联，双击即可用浏览器打开，不需要安装，也不发起网络请求。放静态托管（GitHub Pages 等）同样只需这一个文件。

## 输入与输出

### 输入（左栏「配置」）

| 项 | 说明 |
|---|---|
| 部位 | 生之花 / 死之羽 / 时之沙 / 空之杯 / 理之冠 |
| 主词条 | 可选项依部位而定；花与羽固定 |
| 初始 | 掉落时可见的副词条数，3 或 4 |
| 副词条 | 4 个槽位各自的词条与**计分权重**。权重 0 表示「该词条已知但不计分」 |
| 初始档位 | 掉落那一次成长取第几档。「随机」= 四档等概率 |
| 目标分数 | 指标卡与参考线用 |

### 输出

| 输出 | 含义 |
|---|---|
| 掉落概率 | 能不能刷到这件胚子：`P(主词条 \| 部位) × P(副词条 ⊇ 计分词条)`，**不含成长** |
| 达到概率 | 练满后得分 ≥ 目标分数的概率 |
| 大致要刷 | 按 `1/p` 估算，单位「个胚子」 |
| 概率分布 | 每个可能分数的概率，按命中次数堆叠；柱数过多时自动分桶 |
| 达到概率曲线 | `P(得分 ≥ 分数线)`；悬停显示该分数线**以上**命中次数的条件分布 |
| 命中次数 | 各命中档的总概率与对应刷取次数 |
| 分位分数线 | 前 10% / 1% / 0.1% 对应的分数线 |
| 质量分布 / 组合概率 / 词条概率 | 掉落瞬间的胚子质量：期望得分、最常见副词条组合、单个词条出现概率 |

## 模型

五星圣遗物满级 +20，共 **5 次成长**，终态**一定有 4 个副词条**：

- **4 词条胚子**：5 次成长分配给 4 个槽位，每个槽位至少吃到 1 次（掉落那一次）。
- **3 词条胚子**：第 1 次成长用于激活第 4 个副词条，**这一次就是它的初始档位**（游戏内第 4 条一出现就带档位值），剩 4 次再分配。

每个槽位被成长 `d` 次时有 `4^d` 条等权序列（每次 4 档）。得分是所有槽位成长值乘各自权重后求和：

```
得分 = Σ_槽位 ( 该槽位成长值之和 × 该槽位权重 )
命中次数 = Σ_计分槽位 被成长的次数 − 计分槽位数
```

命中次数里减掉的那部分即掉落时的初始档位——它不是成长。

## 开发

前端用 Vite + TypeScript，不上框架，图表手写 SVG。需要 Node 20+ 与 pnpm（实测 Node 24.21 / pnpm 11.7）。

```bash
cd web
pnpm install
pnpm dev          # 开发服务器
pnpm build        # 构建 → 仓库根 index.html
pnpm test         # 单元测试
pnpm typecheck    # 类型检查
pnpm gen:baseline # 重新导出回归基线（仅在有意更新基线时运行）
```

`pnpm build` 只产出 `index.html`，不产出任何中间资源目录。

Python 侧工具需要 `numpy` / `pandas` / `matplotlib` / `openpyxl` / `seaborn`，在仓库根目录运行：

```bash
python -X utf8 tools/verify_math.py     # 数学交叉验证，退出码 0 = 通过
python -X utf8 tools/bench.py           # 性能基准
python -X utf8 tools/gen_fixtures.py    # 从归档实现导出对拍固件
```

## 数值口径

**全程整数运算，不用浮点。** 分数放大 1000 倍、权重原样参与乘法（`成长值 × 1000 × 权重` 恒为整数），最后一次性四舍五入到 0.1。

归档实现用浮点累加、末尾按 `f'{x:.1f}'` 取整，结果依赖二进制浮点误差，换个语言或换个求和顺序就会漂移。此处**有意不与其逐位复刻**。差异见 `docs/ai-output/1-refactor/01-code-review.md`。

一处必须保留的自洽性断言：全表权重之和恒等于归一化常数（3 词条 `4^12`，4 词条 `4^14`）。它能在结果「看起来正常」时抓住归一化被破坏之类的错误。

## 验证

单元测试分三类，不为覆盖率而写：

- **基线回归**：与 `src/core/__fixtures__/baseline.json` 逐格比对。
- **不变量**：权重和 == 总数、概率和为 1、单调性、路径数为 `4^d`。
- **界面冒烟与结构**：jsdom 挂载 + 交互；SVG 真的画出了柱子 / 曲线 / 扇形。

构建产物单独校验（`tests/build-output.test.ts`）：内联脚本必须通过 `node --check`，不得残留外部引用，不得产出中间资源目录。产物是本项目唯一的交付物，而打包、内联、HTML 解析这三步都不在单元测试覆盖范围内——白屏事故在这类测试里完全看不见。

Python 侧 `tools/verify_math.py` 用独立重写的参考实现对归档实现做交叉验证，退出码 0 即通过。

## 已知的口径不确定性

以下几项缺少权威来源，代码里做成可配置项而非写死：

- **掉落时初始档位的真实分布**未知（是否等概率、是否偏低档）。当前只能在「四档等概率」与固定某一档之间选择。
- **各获取途径的 3 / 4 词条比例**未知。当前一次只算一种胚子，不做混合。
- **成长值只有游戏内显示的一位小数精度**，累加后与官方数值可能有细微出入。
- 掉落概率不含「一次副本掉几件」，因此不能直接读成「刷多少次副本」。
